# Типовые задачи

## Добавить игру и товары (без программиста)

Всё делается в админке admin.redonate.gg → «Каталог»:

1. **Игра**: название, обложка, тип (игра / сервис), поля, которые спросить у покупателя (ID, сервер, почта…). Ниже — SEO-поля (см. [SEO.md](SEO.md)).
2. **Раздел** («Алмазы», «Наборы»): способ выдачи, свои поля покупателя (перекрывают поля игры), описание.
3. **Товары**: название, цена **в долларах** — рубли посчитаются по курсу. Для товаров «за единицу» добавьте поле типа «Количество».

Ускорители:
- импорт CSV из GGSEL (кнопка импорта в каталоге, `api/services/ggsel_import.py`);
- молния у раздела — номиналы FazerCards с автовыдачей.

## Изменить таблицу в БД

1. Поправить модель в `shared/models/*.py`.
2. Создать миграцию в `migrations/versions/` со следующим номером: `NNN_короткое_описание.py`, `revision = "NNN_короткое_описание"`, `down_revision` = revision предыдущей (например `"038_admin_sessions"`). Можно сгенерировать: `alembic revision --autogenerate -m "..."`, затем переименовать и проверить вручную.
3. Обновить схемы `api/schemas/*`, сервисы и фронт (`miniapp/src/api/*.ts`), которые используют эти поля.
4. Миграция применится сама при деплое (сервис `migrations`).

Удалять и переименовывать колонки только в два шага: сначала код перестаёт ими пользоваться (деплой), потом отдельная миграция удаляет колонку.

## Новый эндпоинт API

1. Логика — метод в нужном `api/services/*_service.py`.
2. Схема ответа — в `api/schemas/`.
3. Обработчик — в `api/routers/*.py` (магазин) или `api/routers/admin/*.py` (админка: зависимость `require_permission("...")`).
4. Новый роутер подключается в `api/main.py` или `api/routers/admin/__init__.py`.
5. Клиент на фронте — функция в `miniapp/src/api/index.ts` или `admin.ts`.

## Новая фоновая задача

1. Функция с `@celery_app.task(name="worker.tasks.<файл>.<функция>")` в `worker/tasks/<файл>.py`. Работа с БД — через `get_worker_db_session()`.
2. Файл добавить в `include` в `worker/main.py`.
3. Если по расписанию — запись в `beat_schedule` там же.

## Новый текст бота

- Тексты бота магазина — в `bot/utils/texts.py`.
- Часть экранов бота (приветствие, фото) редактируется из админки: «Настройки → Контент» (`shared/content/registry.py` — список редактируемых текстов, значения — в `shop_settings`).
- Любая строка из БД или от пользователя внутри HTML-тегов — через `html.escape`.

## Сотрудники и права

Админка → «Сотрудники» (доступно только роли owner). Роли и права — `AdminUser.has_permission` (`shared/models/support.py`); проверка в API — `require_permission(...)` из `api/deps_admin.py`. Все действия пишутся в журнал (`admin_action_log`, раздел «Журнал»).

## Проверить изменения перед пушем

```bash
python -m ruff check api bot support_bot worker shared   # линтер
pytest tests/                                            # тесты
cd miniapp && npx tsc --noEmit -p .                      # типы фронта
```

После пуша в `main` проследите за запуском в GitHub Actions. Затем откройте сайт и проверьте изменённое место вживую.
